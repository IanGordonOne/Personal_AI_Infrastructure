# TourGuide — Interactive Codebase Tour

Guide users through **any project's codebase** using a per-project tour definition (`TOUR.md`). Two tour modes: a deep guided tour with interactive stops or a quick overview. If no tour definition exists, offers to generate one interactively.

## Customization

**Before executing, check for user customizations at:**
`~/.claude/skills/CORE/USER/SKILLCUSTOMIZATIONS/TourGuide/`

If this directory exists, load and apply:
- `PREFERENCES.md` - User preferences and configuration

These define user-specific preferences. If the directory does not exist, proceed with skill defaults.

## Voice Notification

**When executing a workflow, do BOTH:**

1. **Send voice notification**:
   ```bash
   curl -s -X POST http://localhost:8888/notify \
     -H "Content-Type: application/json" \
     -d '{"message": "Running the WORKFLOWNAME workflow from the TourGuide skill"}' \
     > /dev/null 2>&1 &
   ```

2. **Output text notification**:
   ```
   Running the **WorkflowName** workflow from the **TourGuide** skill...
   ```

**Full documentation:** `~/.claude/skills/CORE/SYSTEM/THENOTIFICATIONSYSTEM.md`

**Additional voice narration:** TourGuide is a spoken experience — like a museum audio guide. At every stop, transition, and demo result, the tour guide speaks aloud via the notification server. All calls are fire-and-forget; if the server is down, the tour still works.

## Tour Quality Levels

Tours come in two quality levels, determined by the `version` field in TOUR.md:

| Version | Level | Content | Generated By |
|---------|-------|---------|--------------|
| v0 (absent or `"0"`) | **Index** | File paths, brief narratives, demo commands. Fast to generate, good for orientation. | GenerateTour → "Quick reference" depth |
| v1 (`"1"`) | **Teaching** | Rich prose, inline concepts, exercises, warnings, ASCII mockups, glossary. Full learning experience. | GenerateTour → "Teaching tour" or "Deep dive" depth |

All v1 fields are optional — a v0 tour works unchanged with the v1 skill.

| **WorkflowDoc** | Complementary. WorkflowDoc answers "how do I do this?" with step-by-step interaction walkthroughs. TourGuide answers "what can this do?" with narrative codebase tours. Tour stops can reference walkthroughs via `connectsTo`. |

## TOUR.md Location

The tour definition lives at `<project-root>/.claude/TOUR.md`. This is the only supported location. The file is **not tracked in version control** — it's a local asset, regenerable via `generate tour`.

## Missing TOUR.md Handling

If a trigger fires and no `.claude/TOUR.md` exists:

1. Inform the user: "This project doesn't have a tour definition yet."
2. Offer to generate one: "Want me to create one?"
3. If accepted, switch to the **GenerateTour** workflow.
4. After generation, offer to immediately run the tour.

## Tour Depth

Tour depth scales with the TOUR.md content:
- **Minimal tour** (3 stops) — small projects, quick onboarding
- **Standard tour** (5-7 stops) — typical projects
- **Teaching tour** (5-10 stops) — v1 with concepts, exercises, narratives
- **Deep tour** (8-14 stops) — v1 with full OPERATE-level content

## Examples

**Example 1: Full guided tour**
```
User: "Give me a tour of the codebase"
→ Invokes GuidedTour workflow
→ Reads .claude/TOUR.md, loads all stops
→ Walks through each stop with voice narration, file references, and demo commands
→ Output: Interactive stop-by-stop tour with spoken audio at each transition
```

**Example 2: Quick overview**
```
User: "What can this project do?"
→ Invokes QuickOverview workflow
→ Reads TOUR.md overview section + keystone files
→ Output: Condensed elevator pitch with key capabilities and architecture summary
```

**Example 3: Generate a tour for a new project**
```
User: "Generate a tour for this project"
→ Invokes GenerateTour workflow
→ Analyzes codebase structure, identifies key modules and entry points
→ Interviews user about which areas to highlight
→ Writes .claude/TOUR.md with stops, narratives, and demo commands
→ Offers to immediately run the generated tour
```
